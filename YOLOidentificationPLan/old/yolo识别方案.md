# YOLO 识别方案

## 一、硬件约束

本方案的落地前提是当前部署环境存在明确硬件限制，需在以下条件下完成识别能力设计与实现：

- 芯片平台：`RK3588`
- NPU 资源：`3 核 NPU`
- 内存限制：`3G 内存`

因此，整体方案不能采用过重、过长、过多模型级联的设计，而应优先选择主干清晰、链路可控、资源占用可收敛的识别方案。

## 二、方案目标

本方案完全按照当前流程图和需求设计，并且以 `RK3588 + 3 核 NPU + 3G 内存` 为硬件边界，以 `YOLOWorld` 作为统一入口模型，对输入图片或视频帧先做开放词表的 tag 识别，再根据命中的 tag 分流到不同检测链路。整体上只保留三类核心技术栈：`YOLOWorld`、`RapidOCR`、`Retainaface + ArcFace`。其中 `YOLOWorld` 负责主干筛选和标签触发，`RapidOCR` 负责涉政与游行集会中的文字/标语识别，`Retainaface + ArcFace` 负责人脸检测、裁剪与敏感人脸比对。

当前共覆盖 10 个类别，分为三类处理方式：

1. `RapidOCR` 相关：涉政、游行集会
2. 人脸识别相关：落马官员、劣迹艺人
3. tag 直接出结果相关：暴恐、违禁毒品、非法宗教、赌博、纳粹符号、不雅手势

## 三、总体流程

整体流程与当前流程图保持一致：

`输入 -> YOLOWorld -> 根据 tag 分流 -> 输出类别结果`

具体分为以下三条判定链路：

### 1. tag 直接返回链路

对于视觉特征较强、可以直接通过 tag 判断的类别，`YOLOWorld` 命中后直接输出结果，不再进入额外模型。

适用类别包括：

- 暴恐
- 违禁毒品
- 非法宗教
- 赌博
- 纳粹符号
- 不雅手势

这条链路的特点是简单直接、推理链路短、响应快，适合作为主干的快速判定路径。

### 2. RapidOCR 规则判定链路

对于仅靠视觉 tag 不够稳定、还需要结合画面文字内容进行判断的类别，先由 `YOLOWorld` 命中相关 tag，再进入 `RapidOCR` 做文字识别，最后根据关键词或规则输出结果。

适用类别包括：

- 涉政
- 游行集会

其中：

- **涉政**：先由 `YOLOWorld` 命中政治相关 tag，再通过 `RapidOCR` 识别画面中的标语、横幅、字幕或其他文本，最后依据政治关键词和业务规则判断是否返回“涉政”。
- **游行集会**：先由 `YOLOWorld` 命中如 `flag`、`person` 等相关 tag，再通过 `RapidOCR` 判断画面中是否存在标语、横幅、口号等文本信息，最后依据规则判断是否返回“游行集会”。

这里强调一点，`RapidOCR` 的职责是**识别文字内容**，不是做图形符号识别，因此它适合处理“标语、横幅、字幕、口号”这类信息，而不适合承担纯图形类违规内容的主识别任务。

### 3. 人脸识别链路

对于敏感人物相关类别，先由 `YOLOWorld` 命中 `person` 等相关 tag，再进入人脸识别链路。

流程如下：

1. `YOLOWorld` 命中 `tag: person`
2. 使用 `Retainaface` 做人脸检测
3. 对检测到的人脸区域进行裁剪
4. 使用 `ArcFace` 提取人脸特征并做人脸比对
5. 返回人物姓名
6. 根据人物库标签判断该人物是否属于敏感人物类别，并输出最终类别

该链路对应的类别包括：

- 落马官员
- 劣迹艺人

也就是说，人脸链路不是直接返回“有人脸”，而是先返回具体姓名，再根据人物标签映射到最终业务类别。

## 五、核心技术栈说明

### 1. YOLOWorld

`YOLOWorld` 是本方案的主干入口模型，也是整个系统的核心。它负责对输入画面做统一的开放词表识别，输出各类业务相关 tag，并作为后续链路的触发条件。

在本方案中，`YOLOWorld` 承担三项职责：

1. 识别正常画面，直接输出 `normal`
2. 识别不良画面相关 tag，并对 6 个直接分类类别直接返回结果
3. 为 `RapidOCR` 链路和人脸识别链路提供触发条件

因此，`YOLOWorld` 不是辅助模型，而是整个审核流程的统一入口和核心分流器。

### 2. RapidOCR

`RapidOCR` 主要用于处理画面中的文字信息，重点服务于以下两类场景：

- 涉政：识别政治相关标语、字幕、横幅、口号
- 游行集会：识别集会场景中的标语、横幅、文字内容

`RapidOCR` 的价值不在于替代 `YOLOWorld`，而在于补充 `YOLOWorld` 对文本内容感知不足的问题。它负责把画面中的文本提取出来，再由上层规则做业务判定。在当前方案里，它就是实际采用的 OCR 落地实现。

### 3. Retainaface + ArcFace

`Retainaface + ArcFace` 组成完整的人脸识别技术栈：

- `Retainaface`：负责人脸检测与定位
- `ArcFace`：负责人脸特征提取与身份比对

这套组合用于处理敏感人脸识别需求，最终输出具体人物身份，并进一步映射为“落马官员”或“劣迹艺人”等业务类别。

## 六、结果输出方式

系统输出遵循“命中哪条链路，就返回对应类别”的原则：

- 命中 `normal` tag，返回正常
- 命中 tag 直接返回链路，返回对应违规类别
- 命中 `RapidOCR` 链路，结合 OCR 文本与规则后返回涉政或游行集会
- 命中人脸识别链路，先返回姓名，再根据人物属性返回落马官员或劣迹艺人

## 七、方案结论

本方案以 `YOLOWorld` 为统一主干，以 `RapidOCR` 和 `Retainaface + ArcFace` 为两条补充能力链路，结构简单，路径清晰，并且与当前流程图完全一致。10 个类别被明确拆分为 OCR 相关、人脸识别相关、tag 直接出结果相关三大类，便于后续实现、测试和讲解，同时也更符合 `RK3588 + 3 核 NPU + 3G 内存` 的硬件约束。对于现阶段需求，这是一套最小可行且表达清晰的识别方案。
