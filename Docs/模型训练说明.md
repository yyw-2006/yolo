# 模型训练与优化说明

本项目包含两个主要模型：用于目标检测的 **YOLOv8** 模型和用于人脸识别的 **ArcFace**（InsightFace）模型。以下是后续优化这两个模型的指南。

## 一、 YOLOv8 目标检测模型优化

当前项目使用的是预训练的 YOLOv8 模型（如 `detector_19class.pt`）。如果需要提高特定类别（如违禁品、特定标志）的召回率或准确率，或者新增检测类别，可以按照以下步骤进行微调（Fine-tuning）。

### 1. 数据收集与标注
- **收集数据**：针对容易误报（False Positive）或漏报（False Negative）的场景，收集更多真实场景图片。
- **数据标注**：使用 [Label Studio](https://labelstud.io/)、[CVAT](https://www.cvat.ai/) 或 [AnyLabeling](https://github.com/vietanhdev/anylabeling) 等工具进行边界框（Bounding Box）标注。
- **格式转换**：将标注结果导出为标准的 YOLO 格式（每个图片对应一个 `.txt` 文件，内容为 `class_id x_center y_center width height`）。

### 2. 数据集准备
构建符合 YOLOv8 要求的目录结构：
```text
dataset/
├── images/
│   ├── train/
│   └── val/
└── labels/
    ├── train/
    └── val/
```
更新或创建 `data.yaml` 文件，定义类别数量和名称：
```yaml
path: ../dataset
train: images/train
val: images/val

nc: 19
names: ['gun', 'knife', 'blood', 'syringe', 'powder', 'swastika', 'nazi_symbol', 'poker_card', 'dice', 'chip', 'roulette', 'slot_machine', 'middle_finger', 'crowd', 'flag', 'banner', 'signboard', 'police', 'face']
```

### 3. 模型训练
使用 `ultralytics` 库进行训练。建议在带有 GPU 的机器上运行：
```bash
pip install ultralytics
yolo detect train data=data.yaml model=yolov8m.pt epochs=100 imgsz=640 batch=16 device=0
```
*注：`model` 可以选择 `yolov8n.pt` (Nano, 最快), `yolov8s.pt` (Small), `yolov8m.pt` (Medium) 等。*

### 4. 模型导出与替换
训练完成后，最佳权重将保存在 `runs/detect/train/weights/best.pt`。
将其复制到项目的 `weights/` 目录下，并更新代码中的模型路径。

## 二、 ArcFace 人脸识别模型优化

项目中人脸识别使用的是 InsightFace 提供的预训练模型（RetinaFace 提取特征点，ArcFace 提取特征向量）。通常情况下，**不需要重新训练 ArcFace 模型本身**，因为其泛化能力已经足够强。

优化人脸识别（特别是针对“涉政”人物的识别）的核心在于**更新和扩充底库（Facebank）**。

### 1. 扩充人脸底库 (Facebank)
当发现某位政治人物无法被正确识别时，需要将其照片加入底库：
1. **收集照片**：收集该人物的高清、正脸、不同角度和光照条件下的照片（建议 3-5 张）。
2. **提取特征**：使用项目中的人脸特征提取脚本（如 `person_facebank_full.npz` 的生成脚本），对这些新照片提取特征向量。
3. **更新底库文件**：将新提取的特征向量追加到 `person_facebank_full.npz` 中，并同步更新对应的清单文件 `person_facebank_full_manifest.json`。

### 2. 更新名单配置
如果新增了政治人物，必须在 `data/political_persons.txt` 中添加该人物的姓名（需与 Facebank 中注册的姓名完全一致），否则业务规则层无法将其映射为“涉政”标签。

### 3. 调整匹配阈值
如果发现人脸识别存在误识别（把普通人认成政治人物）或漏识别：
- **误识别过多**：在代码中**提高**余弦相似度的匹配阈值（如从 `0.45` 提高到 `0.55`）。
- **漏识别过多**：在代码中**降低**余弦相似度的匹配阈值。
*注：阈值调整需要在测试集上进行充分验证，以找到最佳的 Precision-Recall 平衡点。*

## 三、 业务标签映射规则修改

如果需要新增、删除或修改从底层类别到业务标签的映射逻辑，需要修改代码中的映射函数。

### 1. 修改映射代码
打开 `scripts/recognize.py` 文件，找到 `map_business_category` 函数：

```python
def map_business_category(
    categories: list[str],
    face_count: int,
    face_recognition: dict | None,
    political_person_names: set[str],
) -> str:
    def has(label: str) -> bool:
        return label in categories

    # 在此处修改或新增判断逻辑
    if has_political_person(face_recognition, political_person_names):
        return "涉政"
    # ... 其他规则
```

**修改原则**：
- 规则按从上到下的顺序执行，**优先级高的规则放在前面**。
- 使用 `has("类别名")` 来判断是否检测到了某个底层类别。
- 可以结合 `face_count`（人脸数量）等其他条件进行复合判断。

### 2. 同步修改评估脚本
修改了映射规则后，必须同步更新评估脚本中的期望类别映射，否则测试结果会不准确。

打开 `scripts/evaluate.py`，找到 `EXPECTED_CLASSES` 字典并进行相应的修改：

```python
EXPECTED_CLASSES = {
    "暴恐": ["gun", "knife", "blood", "police", "riot_shield"],
    # ... 根据新的映射规则更新此处的列表
}
```
修改完成后，重新运行 `python scripts/evaluate.py` 验证新的映射规则是否符合预期。
